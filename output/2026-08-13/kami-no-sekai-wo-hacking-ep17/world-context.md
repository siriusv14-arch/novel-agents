**ep16終了時点の状態**

## 2. ep17に関係する世界設定

### 2-1. 記録庫地下の物理的設定（ep16本文より確定済み）

**入口（地上の記録室内）**
- 棚の終わり（突き当たり）が石の壁
- 棚と壁の間に、人が横向きになれば通れる隙間がある
- 隙間の向こうに低い木の扉（高さが目の位置よりも低い）
- 鍵穴が一つ、正面にある
- 扉の表面に「分類外保管」と刻まれている
- 鍵はかかっていない（昼間に確認済み）

**地下の構造（ep16本文より）**
- 石の段が下へ続く。段の数: 十三段
- 明かりは壁の燭台が一つだけ（昼間にテルが壁から外して持ち込んだ）
- 湿った空気。石と古紙の匂いが重なっている
- 天井が低い。壁がすぐそこにある
- 棚が並んでいる。分類記号の板がない。背に何も書いていない束もある
- 一番奥の棚の最下段に目的の束がある

**夜間の追加条件**
- 建物内は昼間より暗い（燭台/灯りが減る）
- テルが地下の燭台を「昼間は壁から外した」（→ 今度は持参するか、再度壁から取るか）
- 廊下に人が少ない時間帯（術士のすれ違いが発生しにくい）
- 夜に建物内を一人で動いていること自体が、発見された場合に説明が必要になる状況

**要確認-A（燭台の扱い）**
ep16で「持ち出していい場所ではないかもしれない。でも、置いてきたら、手元も見えない」と描写されている。テルは昼間に燭台を壁から外して持ち込み、最終的に「燭台を、拾った。十三段を、上がった」と記録室へ戻した。今夜再び降りる際には同じ燭台を使うはず。テルが部屋から灯りを持参するか、記録室の燭台（または地下の燭台）を再利用するかは描写上の確認が必要。

### 2-3. value-queryの応用（ep17の技術軸）

**ep16で確立した手法**
```
> describe --target=NODE-07 --field=format_series --value-query=QY-001
```
→ `[format_series: 参照可 / マーカー照合による部分開示]`
→ `[QY-001: 初代規格 / 現行に先行する定義 / 移行ステータス: 継続中]`
→ `[継承先: QY-007]`

**ep17での応用可能性**
bundle内の別の値（送信元・応答間隔の具体数値）を使って新たなvalue-queryを打つことができる。

命名規則との整合（推定フィールド候補）:
- `describe --target=NODE-07 --field=source_origin --value-query=[送信元の値]`
- `describe --target=NODE-07 --field=interval_log --value-query=[応答間隔の値]`
- または新規フィールドではなく、同じformat_seriesへの追加照合

**技術ガイドライン（ep16までの命名規則）**
- コマンド形式: `> describe --target=NODE-07 --field=フィールド名 --value-query=値`
- 返り値形式: `[フィールド名: 値]` の角括弧＋コロン形式
- フィールド名はスネークケース（アンダースコア区切り）
- 「参照可 / 〇〇による部分開示」という返り方が今章の発展型として自然

## 4. ep16からep17への接続

**ep16の終わり方**
```
今夜、もう一度降りる。二枚の先に何があるかは、今夜でなければ分からない。
```

**ep17の接続として設定的に自然な展開構造**

1. **夜の準備/移動**（短く）
   - テルが部屋で灯りを確保する（燭台・または別の手段）
   - 建物内が静かになった時間帯を選ぶ（誰かとすれ違う可能性を意識）
   - 記録室へ。棚の突き当たりへ。低い扉へ

2. **地下での調査（今章の中心）**
   - 十三段を降りる。昼間と同じ空間、夜の感覚で異なる点を一文で描写
   - 最下段の束を再び引く。三枚目から読み始める
   - 手書きの内容が展開する。接続形式の詳細・送信元の記録・応答間隔の数値
   - 新たな値でvalue-queryを試みる（またはその試みが今章末の判断として保留される）

3. **イレーネとの短い接触（可能性あり）**
   - 地下から戻る際または廊下で、イレーネと出会う
   - 端的な言葉のやり取り（2〜3行以内）
   - テルが「伝えるべきか」「まだ確かめる前」という内部葛藤を持ちながら、結論を保留する

4. **章末の状態（提案）**
   - 束の新情報を読み終えて整理する内部描写
   - 新たに開いた問い（送信元の候補・「継続中」の意味・七十三年前の人物の調査の目的）
   - 翌朝イレーネに報告するか否か、という保留を持って閉じる

**接続トーンの設計**
- ep16は「昼間の発見・決意」の章。ep17は「夜の実行・読了・新たな問い」の章
- ep16は「値が鍵だった」という方法論の発見で閉じた。ep17は「鍵を使って開いた先」にある内容との格闘
- 夜という時間帯が「静けさ・緊張・一人で向き合う感覚」を強める
- 技術的な発展（value-queryの応用）と、「七十三年前の人物を追体験する感覚」が交差する

## 8. 執筆ガイドライン（ep17用）

### 描写の基本方針（world-settings.md §11より）
- 「誰が・どこで・どんな表情・動作で」を各シーンに必ず入れる
- 過剰な修飾語は使わない。一文で情景が見えるレベルに留める
- あとがきは記載しない

### テルの感情描写
- ep16での「値が鍵だった」という方法論的発見の静かな手応えを持って夜に向かっている
- 焦りも急ぎもない。「二枚の先に何があるかは、今夜でなければ分からない」という淡々とした確信
- 七十三年前の人物の手書きを「再び読む」という行為——先達の思考を追う読書体験に近い感覚
- 束の内容が「形式から辿れ」という指示と連動していると気づいた時の内部反応を丁寧に描く

### 夜の地下の雰囲気
- 静けさと暗さを活かす。昼間の地下との対比（昼間も暗かったが、周囲の建物の音は聞こえていたはず）
- 燭台一本の揺れる光の中でページを繰るという物理的感覚
- テルが「長く地下にいすぎると誰かに見つかる可能性」を意識している緊張感（しかし動きを止める理由にはならない）

### 黒板コマンドの描写方針
- value-queryの応用が今章の技術的核心（ep16で確立した手法の継続）
- 新しい値を持ち込んだ時の「返ってくる・返ってこない」の緊張感
- ep16での「参照可が、返った」という手応えの再現または深化
- コマンドは2〜3行。コードより内省の比重を上げる（ep9以降の定番方針）

### テンポと情報開示
- 今章は「調査の継続と深化」の章
- 「送信元の完全特定」は今章では行わない。「手がかりが増えた」「問いが具体化した」という一段階の前進
- イレーネとの接触は短く。テルの内部での「伝えるか伝えないか」の迷いと、「まだ確かめていない」という保留が読者の期待を維持する

### 前世との接続（オプション）
- 七十三年前の手書き束を読む体験が「前世でサーバーインシデントの記録を読んでいた時の感覚」と重なる瞬間があると、テルのキャラクター深度が増す
- ただし前世の具体的な開示（F-08）は第2章まで抑制。内部回想として一行程度にとどめる
