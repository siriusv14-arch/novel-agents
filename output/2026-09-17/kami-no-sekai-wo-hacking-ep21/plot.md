## 章の目的

ep20で「照合主体: UNDEFINED」という応答を得た。「空ではない。定義の枠が、ない」という内部言語化で終わった。
今章の核心は「UNDEFINEDそのものに問うことの不可能性」と「しかしUNDEFINEDが照合という行為をしているという事実」の間にあるギャップを埋めること。
テルがUNDEFINEDを直接問おうとして失敗し、「アプローチの向きを変える」転換が起きる。
章末で「向こうは、こちらを、見ていた」という認識がテルに生まれ、次章への問いが立つ。

**感情の山場:** 一つ。夜の黒板でverify_triggerへの応答を読んだ瞬間——自分の問いがトリガーになっている、という発見の静かな衝撃。

## シーン構成

### シーン1：朝 / 机・黒板

**位置づけ:** ep20の発見（照合主体: UNDEFINED）を受けた直接のアプローチ。UNDEFINEDに正面から問う。

**やること:**
- ep20の夜、「照合主体: UNDEFINED」を見て黒板を伏せた。朝、また起こす。
- 「UNDEFINED」という言葉を対象に、直接問いを立てようとする。

**コマンドと返り:**
```
> describe --target=UNDEFINED --field=identity
```
返り:
```
[エラー: 照合対象が解決できません]
[UNDEFINED は有効なターゲット識別子ではありません]
```

続いて別アプローチ:
```
> describe --target=NODE-07 --field=format_series --value-query=QY-001 --field=verify_source
```
返り:
```
[format_series: 参照可 / マーカー照合による部分開示]
[QY-001: 初代規格 / 移行ステータス: 継続中]
[verify_source: 非公開 / アクセス権限不足]
```

**テルの内部:**
- UNDEFINEDそのものは問えない。名前がないものは、問い先にできない。
- verify_sourceも権限不足で返ってきた。
- （……やはり、正面からは届かない）
- 「定義の枠がない」ということは、問いの対象として指定する形式そのものが通じない。
- どう問えばいいか、まだ分からない。

**Show, don't tell:**
- テルが黒板のエラー行を指でなぞる（「エラー」という言葉を読み直す動作）
- 返りを一行ずつ読む動作として描写

### シーン4：夜 / 机・黒板 / 章の山場

**位置づけ:** イレーネのヒントを受けた新しいアプローチ。「向こうがしていること」を観察する。

**やること:**
- 夜、机に戻る。黒板の面を起こす。
- イレーネの言葉を頭の中に置いてから、指を動かす。
- 「照合の痕跡」を問う方向に切り替える。

**コマンドと返り（前半）:**
```
> describe --target=NODE-07 --field=format_series --value-query=QY-001 --field=verify_log
```
返り:
```
[format_series: 参照可 / マーカー照合による部分開示]
[QY-001: 初代規格 / 移行ステータス: 継続中]
[verify_log: 存在する / 内容: 非公開]
[最終照合: 直近]
[照合頻度: 不定期]
```

**テルの読み方（前半）:**
- verify_logが「存在する」と返ってきた。中身は見えない。でも記録はある。
- 「最終照合: 直近」——今も照合が続いている。
- 「照合頻度: 不定期」——定期ではない。何かのタイミングで来ている。
- （……タイミングは何だ）

**コマンドと返り（後半）:**
```
> describe --target=NODE-07 --field=format_series --value-query=QY-001 --field=verify_trigger
```
返り:
```
[verify_trigger: 外部入力 / 照合開始条件: 非公開]
[直近トリガー記録数: 複数 / 最終記録: 直近]
```

**テルの内部（山場）:**
- 「外部入力」。
- 何かが入力されるたびに照合が起きている。
- 「直近トリガー記録数: 複数」「最終記録: 直近」。
- （……今夜、黒板に問いを打ち込んだ）
- （……その「入力」が、トリガーになっている、ということか）
- 自分が問いを打つたびに、向こうが照合している。
- （……向こうは、こちらを、見ていた）

**章末（引き）:**
- テルが黒板の明かりに照らされたまま、もう一行打とうとして——止まる。
- 内部思考として: 「（……どこから、見ている）」

**描写の注意:**
- 山場の発見は「驚き」ではなく「静かな確認」として書く。テルは感情的にならない。
- コードブロックを挟みながらテルの内部思考が動く構造を維持。
- 最後の「どこから、見ている」は、次章への問いとして章末に置く。解決しない。

## 用語解説（章末に追加）

今章で新出または重要な概念：

- verify_log（照合ログ）：照合が行われた記録。いつ・どのような照合が行われたかの履歴。中身が非公開でも「ログが存在する」こと自体を確認できる場合がある。ログの存在は「誰かが照合している」という証拠になる
- verify_trigger（照合トリガー）：照合が開始されるきっかけとなる条件。定期的に発生するものと、特定の外部入力に反応して発生するものがある。「外部入力」がトリガーの場合、システムへの操作や問いかけそのものが照合を引き起こしている可能性がある
