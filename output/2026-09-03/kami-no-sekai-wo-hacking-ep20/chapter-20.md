ep.20　第1章 第17話：上流（アップストリーム）―― 届いているものには、源がある

朝、黒板の前に座った。

昨夜から、同じ問いだった。誰が、QY-001を、続かせているのか。

七十三年以上。003から006は全部、移行ステータスが完了している。役目を終えている。001だけが、今も何かを渡している。渡し先はNODE-07だ。この部屋から毎日叩いている、あのノードだ。

受信側は分かった。送信側が、分からない。

手を、黒板のコンソールに当てた。

---

NODE-07は受信側だと、前に返ってきた。

ならば、送信側を指すフィールドが、どこかにあるはずだった。フィールド名が分からないだけで、問い方があるはずだった。

最初に思いついた言葉から、試した。

```
> describe --target=NODE-07 --field=transmit_source
```

間があった。

```
[エラー: このノードは受信側です。送信側への問い合わせはこのノードから実行できません]
```

別の言葉で、打ち直した。

```
> describe --target=NODE-07 --field=upstream_node
```

```
[エラー: このノードは受信側です。送信側への問い合わせはこのノードから実行できません]
```

同じ応答だった。文面が、一言一句、変わらなかった。

もう一度、試した。

```
> describe --target=NODE-07 --field=origin_node
```

```
[エラー: このノードは受信側です。送信側への問い合わせはこのノードから実行できません]
```

黒板から、指を離した。

（……構造の問題だ）

エラーの内容が変わらない。フィールド名の問題ではない。NODE-07が受信側であるという事実が、問いそのものを弾いている。どんな言葉で問っても、受信側からは送信側が見えない。

「届いているものには、源がある。ただし、受け取る側からは、源の場所が分からない」

前世で、似たような話を聞いたことがあった。サーバの障害対応で、クライアント側からサーバの内部情報を引き出そうとしても、仕組み上できないことがある。クライアントには「受け取るための口」しかない。

NODE-07も、同じだった。

受信のための口だから、送信した側を見る目を持っていない。

（……上流は、外にある）

NODE-07の外。黒板が届く範囲の、外。

黒板は伏せなかった。面だけを、机の縁に立てかけた。

---

廊下に出た。

階段の手前に、術士が二人立っていた。

「八回になった」

「今朝か」

「昨日の夕方が七回だった。今朝また一回増えた」

テルは足を止めなかった。

（……七回から、八回）

また一日で一回。縮まる速さが、変わらない。いや、変わっていないということは、速さが維持されている。前は数日かけて一回増えていた。それが今は、毎日一回増えている。

その速さが、もう何日も続いている。

七十三年前の束の六枚目を、思い出した。行間が狭くなっていく数字の列。手が急いでいた、あの紙面。

---

シリアの部屋の扉を、三回叩いた。

「はい」

中に入った。シリアが部屋の隅の椅子に座っていた。膝の上に手を置いて、窓の外を見ていた。

「聞いていいか」

「……はい」

「方角。変わっているか」

シリアが少し考えてから、首を横に振った。「変わって、ない」

「感じ方は」

シリアが窓の外を見たまま、少し経ってから言った。「なんか……近くなってる、感じ、がする」

「近くなっている」

「うん。前は、遠くから来てる感じがした。でも、今は……なんか、もうちょっと、こっちの、手前に来てる、みたいな」

テルが手元の紙に書き留めた。距離感の変化。これまでシリアが報告してきたのは、方角と量と質だった。急いでいる感じ、切れ目がない感じ。それが今日、距離感という新しい情報になった。

「急いでいる感じは、続いているか」

「うん。ずっと」「前より……たぶん、もうちょっと、急いでる」

シリアが少し眉を寄せた。「伝えにくいんだけど……なんか、待ってる、みたいな感じ、もする」

「待っている」

「うん。急いで送ってきてるのに、なんか、こっちが気づくのを、待ってるみたいな」

テルは書くのを止めた。

（……向こうは、こちらが辿り着くのを、待っている）

それが事実かどうかは、分からない。シリアの感覚は正確だが、感覚は解釈を含む。けれど、一つのことは言えた。

黒板からは上流は見えない。けれど、シリアには、方角が届いている。

届いているということは、あの方角に、送っている何かがある。送り続けているものが、そこにある。

（……上流は、シリアが指している先にある）

部屋を出る前に、テルはシリアに言った。「ありがとう。また来る」

シリアが小さく頷いた。

---

廊下の角で、イレーネとすれ違った。

イレーネが先に口を開いた。「シリアのところへ行っていましたか」

「はい」

「シリアの方角は、確認しましたか」

テルは一拍止まった。

「確認しました。変わっていませんでした。沿岸部の方向です。今日は、距離感が近くなっているという報告がありました」

イレーネが少し間を置いた。廊下の壁の向こうを見るような顔をしていた。

「そちらに向かう理由が、ひとつ増えましたね」

それだけ言って、歩き出した。

テルは動かないまま、廊下を遠ざかるイレーネの背中を見た。

（……なぜ、この人は、シリアの方角を訊いたのか）

方角が上流への手がかりになるということを、先から知っていたのか。それとも、今朝、同じ結論に来たのか。どちらか、分からない。

「そちらに向かう理由が、ひとつ増えた」という言葉の意味も、分からない。増えたということは、前から向かう理由があったということだ。今日が、初めてではない。

（……また、答えではなく、次の場所を示した）

ただ、今度は、言葉の重さが少し違った。

---

夜、部屋に戻った。

黒板は、立てかけたままだった。

椅子に座って、今日分かったことを、頭の中で並べた。

黒板からは、上流への逆引きはできない。NODE-07は受信側で、送信側を見る仕組みを持っていない。これは構造の話だから、コマンドの工夫で解決するものではない。

上流は、NODE-07の外にある。地理的に、どこかに存在する。

シリアは、七十三年以上、止まらずに届き続けている何かを感じている。その何かは、沿岸部の方向から来ている。今日、距離感が近くなったという報告があった。

（……では、シリアが指している先に、何がある）

机の引き出しから、古い地図を出した。大陸の輪郭を辿る。中央部から、沿岸部へ。神の恩恵が薄れていく方向。黒板が届きにくくなる領域。

その先に、QY-001は七十三年以上、止まらずに何かを送り続けている。

七十三年前の束の八枚目が、思い出された。「なぜ、今も動いているのか」「誰が、続かせているのか」二行しか書いていなかった紙。あの人は、003に来る前に、筆を止めた。

この問いの前まで、来ていたかどうかは、書いていなかった。

テルは地図を折りたたんだ。

答えは出ていない。

ただ、向かう場所が、今日よりひとつ具体的になった。

黒板を、机の上に伏せた。

---

用語解説

アップストリーム（upstream）：データや信号の流れを川にたとえた時の「上流」側のこと。データを送り出している発信源を指す。受け取る側はダウンストリーム（downstream）と呼ばれる。テルが今話で試みたのは「受信側のNODE-07から、送信側（上流）がどこにあるかを問い合わせること」だったが、受信側は構造上、上流の場所を把握していない。黒板の応答「送信側への問い合わせはこのノードから実行できません」は、この仕組みをそのまま返したものだった。

逆引き（reverse lookup）：通常の問い合わせとは逆方向で情報を引き出すこと。受け取ったデータから発信元を特定しようとする試みがこれに当たる。ネットワーク上でIPアドレスからドメイン名を調べる「逆引きDNS」が現実の例として知られる。受信ノードから送信ノードへの逆引きが成立するためには、受信側がその情報を記録・保持している必要があるが、NODE-07にはその記録が存在しなかった。届いたという事実は残っていても、どこから届いたかを受信端点から辿ることはできない
