## 1. 今章の重要な世界設定

### ep19終了時点のテルの到達点

ep19終了時のテルの状態：

- QY-001〜QY-007の全世代連鎖を確認完了
- NODE-07 = QY-007 = QY系列の最末端（第7世代・受信側の最終地点）と確定
- 「外から叩いているつもりでいた」が実は「鎖の列の中に入っていた」という認識転換を経た
- 七十三年前の人物の問い「誰が、続かせているのか」とテルの問いが完全に重なった
- 「（……誰が、001を、続かせている）」という問いを抱えたまま黒板を伏せた
- 「末端が分かるということは、上流があるということだった」という論理的接続が確立

### ep20の調査転換：「上流（誰）」から「型（形式）」へ

ep20の核心は調査の切り口の変更である。

**朝の調査（失敗）：**
テルは「上流」すなわち「誰が001を続かせているか」を黒板で直接問おうとする。
しかし、source / origin / upstream 系のフィールドを問うと、これまでと同様の「アクセス権限不足」または「定義元: 外部」が返る可能性が高い。F-37（root権限より上位の権限体系）の壁に再び当たる。

**イレーネのヒント（廊下）：**
「上流ではなく、型を見てみて」

この一言で調査軸が変わる。「誰が」ではなく「どういう形式で（何型の接続で）」QY-001が維持されているかを問う方向へ。

**夜の調査（新しい切り口）：**
イレーネのヒントを受け、テルは「QY-001の維持形式（接続型）」を問う新しいコマンドを試みる。

既存コマンド形式の拡張として以下が想定される：
```
> describe --target=NODE-07 --field=format_series --value-query=QY-001 --param=connection_type
```

または別フィールドへの問いとして：
```
> describe --target=NODE-07 --field=maintain_type --value-query=QY-001
```

「通常のノード接続と異なる形式」という発見は、QY-001が他のQY-002〜006のような「継承・完了」型（世代を渡したら終わる一方向の引き継ぎ）ではなく、現在進行形で維持され続ける別の接続形式（例：persist_connection、static_binding、live_link 等）で動いていることを示す。

すなわち：
- QY-002〜006 → 「一度渡したら終わる」型（移行ステータス: 完了）
- QY-001 → 「渡しながらも続いている」型（移行ステータス: 継続中）

これは単純な上流・下流の構造ではなく、QY-001が「渡す」と同時に「維持する」という二重の役割を持った異常な形式で接続されていることを示唆する。

### 黒板コンソールの動作仕様（ep20に関係する制約・法則）

**確立済みコマンド形式（ep16以降）：**
```
> describe --target=NODE-07 --field=format_series --value-query=[値]
```
```
> describe --target=NODE-07 --field=format_series --value-query=[値] --param=[パラメータ]
```

**応答パターンの法則（ep16〜ep19で確立）：**
- `[format_series: 参照可 / マーカー照合による部分開示]` → 固定ヘッダ
- `[QY-XXX: [世代名] / [前世代]の後継定義 / 移行ステータス: [状態]]`
- `[継承先: QY-XXX]`
- `[照合記録: N件]`

**ep20での応答形式（想定）：**
型（connection_type / maintain_type）を問うた場合、新しいフィールドが開く可能性がある：
```
[connection_type: 非標準 / 通常継承形式と異なる定義]
[maintain_type: 継続維持 / 終了条件: 未定義]
```
または：
```
[参照可 / 維持形式: アクティブ接続]
[通常継承形式との差異: 移行完了後も発行継続]
```

**応答返答の間隔：** 「昨夜と、同じ長さの間だった」と描写されてきた。ep20でも維持。ただし新しいフィールドを問うた場合、間隔が変わる可能性がある（異常な応答の予兆として使える）。

## 2. 今章に登場するキャラクターの現在状態

### テル（桜井 輝明 / WhiteCrow）

**ep19終了時点の状態：**
- QY-001〜QY-007の世代連鎖を全て確認し終えた
- 「誰が、001を、続かせている」という問いを抱えたまま黒板を伏せた
- 七十三年前の人物と同じ問いの前に立っていることを自覚している
- 問いの形が「昨日より、はっきりしていた」という内部言語化で終了

**ep20での内部軌跡（想定）：**
1. 朝、「上流」を調べようと黒板を叩く（具体的なフィールドを問う）
2. アクセス権限不足または参照不可が返る（壁）

6. 夜、「型」という視点で黒板を叩き直す

8. 「誰が」ではなく「どういう形式で」という問いの転換が起きる

**テルの内部認識の変化（ep20の軸）：**
- ep19まで：「誰が上流にいるか」（主体・人格）
- ep20で：「どういう形式で維持されているか」（型・仕組み）

**口調の注意事項：**
- イレーネへは「〜です/ます」の丁寧語
- 「〜はずです」「〜可能性があります」「〜かもしれない」という推測・仮説表現が多い
- 一文で結論を言い切らず「〜があるとしたら」「〜ということは」と積み上げる
- 技術用語を自然に使う（connection_type、maintain_type、継続維持、発行継続等）
- **内部思考は全角括弧「（……）」で表記。半角混在禁止**（ep14以降全角統一済み）

## 6. 執筆時の注意事項

### 構造的な注意

1. **「上流を問う」失敗から「型を問う」へのシフトを丁寧に描く：** テルが「誰が」という問いを立てて黒板を叩き、壁にぶつかる場面があってから、イレーネのヒントで方向が変わる。この「問いの立て方の転換」がep20の主な内部運動。

2. **「通常のノード接続と異なる形式」の描写：** システム応答として具体的なフィールド値が返る場面で、テルが「QY-002〜006と違う。001だけが、別の型で動いている」と内部言語化する場面が核心。驚きより「やはりそうか」「でも、これは何型だ」という次の問いへの接続として描く。

3. **イレーネのヒントの渡し方：** 長くしない。廊下での一言。説明なし。「上流ではなく、型を見てみて」だけで終わる形が望ましい（イレーネの口調に合致）。

4. **七十三年前の対比を維持：** 七十三年前の人物も「誰が、続かせているのか」という問いで止まった。テルはその先へ進もうとしているが、同じように「誰が」では壁にぶつかる。「型を見る」という視点は七十三年前にはなかった（彼は003に到達できなかった）。テルだけが到達できた先の調査手法という位置づけが使える。

### 場面配置の注意

- **朝の黒板操作：** テルの部屋。「上流」系フィールドを問う → 壁（アクセス不可）。どう問えばいいかを考えながら廊下へ出る。
- **廊下：** イレーネとすれ違い。「上流ではなく、型を見てみて」。短い。
- **廊下（別の場面またはイレーネとのすれ違い前後）：** 術士の「八回になった」を聞く。
- **夜の黒板操作：** 「型」フィールドを問う → 「通常のノード接続と異なる形式」という応答を得る。次の問いへ。

## 7. 今章で新設が想定される用語（章末用語解説候補）

| 用語 | 内容 |
|---|---|
| 接続型 / connection_type | ノード同士が「どういう形でつながっているか」を示す分類。通常継承型（渡したら終わる）と継続維持型（渡しながら続く）の違いがあることをep20で示す |
| 継続維持（persistent connection）| 渡し終わっても接続が終了しない、特殊な維持形式。通常の継承・完了型とは根本的に異なる |
