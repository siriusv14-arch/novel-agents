## 章の目的

ep21で「代替経路: 存在」という応答を受け取った。「どこからなら、訊ける」という問いで終わった。
今章の核心は「代替経路とは何か」を直接問いに行き、「非ノード経路」という種別が返ること。そしてイレーネのヒントを経由して、シリアが「非ノード経路」として機能している可能性をテルが内部で初めて言語化すること。

## シーン構成

### シーン1：朝 / 机・黒板

**位置づけ:** ep21の夜に「代替経路: 存在」を確認した。朝、その「代替経路」を直接問う。

**やること:**
- ep21の夜から黒板を伏せなかった。朝、最後の行がまだある。
- 昨夜の「代替経路: 存在」の行を見ながら、そのフィールドを直接問う。

**コマンドと返り:**
```
> describe --target=NODE-07 --field=alternate_route
```
返り:
```
[alternate_route: 存在]
[種別: 非ノード経路]
[経路数: 非公開]
[接続条件: このノードを経由しない]
[詳細: 非公開 / アクセス権限不足]
```

**テルの内部:**
- 「非ノード経路」。ノードを経由しない道。
- これまでのコマンドはすべて `--target=NODE-07` だった。NODE-07を通じて問いを出していた。
- 「このノードを経由しない」接続が必要だと、システムが返している。
- NODE-07から問い続けているかぎり、この経路には届かない。
- （……経路はある。でも、ここから辿れない）

**Show, don't tell:**
- テルが返りを読みながら指を黒板の「接続条件: このノードを経由しない」の行の上で一度止める動作
- 黒板の明かりに照らされた自分の手を見る一瞬

### シーン3：記録室の前 / イレーネとの短い交換

**位置づけ:** F-28（イレーネの調査動機）・新規-ep17-C（イレーネが知識を持つ理由）の進展。シリアへのヒントを置く。

**やること:**
- 記録室の前にイレーネが立っている。
- テルが「代替経路が返ってきました。種別は非ノード経路、詳細は非公開でした。このノードを経由しない接続が必要だと」と報告する。
- イレーネが短く答える。

**イレーネの一言:**
「窓口を経由しない受け取り方を、もうしている子が、いるでしょう。」

それだけ言って扉を開けて中へ入る。

**テルの内部:**
- （……窓口を経由しない受け取り方をしている子）
- 一人だけ、当てはまる子がいる。
- （……シリア）
- シリアは感知する。NODE-07の接続を開閉しても、シリアへの信号は切れなかった。
- 黒板を経由せずに、直接届いていた。
- あれは、「非ノード受信」だったのかもしれない。

**イレーネの描写（Show, don't tell）:**
- 「窓口を経由しない受け取り方を」と言うとき、テルの顔を見ている。答えを確認しているのではなく、届いたかどうかを確認している目。
- テルが何かを言う前に、扉が閉まる。
- テルが扉を見ながら「また、答えではなく、場所を指した」と内部で認識。

**イレーネの注意事項:**
- 感情表現なし
- シリアの名前を出さない（テルが自力で接続する余地を残す）
- 「なぜ自分がその知識を持っているか」を語らない（F-28・新規-ep17-C継続）

### シーン4：夜 / 机・黒板 / 章の山場

**位置づけ:** イレーネのヒント「窓口を経由しない受け取り方をしている子」を受けたアプローチ。シリアを「非ノード経路」として初めて内部言語化する。

**やること:**
- 夜、机に戻る。
- 「窓口を経由しない受け取り方」という言葉を頭に置いてから、指を動かす。
- 「非ノード受信」という種別を掘り下げるコマンドを打つ。

**コマンドと返り:**
```
> describe --target=NODE-07 --field=alternate_route --field=receiver_format
```
返り:
```
[alternate_route: 存在]
[receiver_format: 非ノード受信]
[照合形式: 外部]
[受信主体の種別: 非公開]
[補足: 当該経路の受信は、ノード外の受信主体を経由する]
```

**テルの読み方（前半）:**
- 「非ノード受信」。
- 受け取る側が、ノードを使っていない。
- 「照合形式: 外部」——またこの言葉。
- 「受信主体の種別: 非公開」——受け取っている主体が何であるかは、返ってこない。

**テルの内部（山場）:**
- （……受信主体が、非公開）
- でも、「ノード外の受信主体を経由する」と書いてある。
- ノードを使わずに受け取っている、何かが存在する。
- 人間か、装置か、別のものか。書いていない。
- 「窓口を経由しない受け取り方を、もうしている子が、いる」——イレーネの言葉が戻ってきた。
- 「子」と言った。装置や仕組みではなく、人間を指す言い方だった。
- （……シリアが、受け取っている）
- シリアは、ずっと、向こうからの信号を感じていた。
- NODE-07の接続を切っても、シリアへの感知は止まらなかった。
- 黒板のping、acknowledge、receiveのどの段階でも、シリアだけには届いていた。
- ノードを経由せずに。
- （……シリアが、非ノード経路だ）

**二行目のコマンドと返り:**
```
> describe --target=NODE-07 --field=alternate_route --field=activation_condition
```
返り:
```
[alternate_route: 存在]
[activation_condition: 非公開]
[補足: 当該経路は現在、使用中です]
```

**テルの内部（章末）:**
- 「使用中」。
- 今も、使われている。
- シリアのところへ、今も、届いている。
- （……向こうは、もう、別の道から来ている）
- （……僕が黒板を叩いている間も、向こうは別の窓口から見ていたのかもしれない）

**章末（引き）:**
黒板の「使用中」の文字を、もう一度読んだ。

## 用語解説（章末に追加）

今章で新出または重要な概念：

- 非ノード経路（non-node route）：ノード（中継点）を通らずに信号や情報が届く経路のこと。通常の通信網はノードを介して経路を確立するが、ノードを使わない受け取り方が可能な場合、システム側はそれを「非ノード経路」として記録することがある。使っている側がノードの存在を意識していない場合も多い

- receiver_format（受信フォーマット）：何が・どのような形式で受け取っているかを定義する属性。ノードが受け取っているのか、ノード外の別の何かが受け取っているのかを区別するために使われる。「非ノード受信」が返る場合、受け取っている主体はノードではない

- activation_condition（起動条件）：ある機能や経路が動作を開始するための条件。「使用中」という補足が返る場合、その経路がすでに誰かによって使用されていることを意味する
