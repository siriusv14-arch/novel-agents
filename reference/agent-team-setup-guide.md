# Claude Code で「AIエージェントチームの定期自動実行」を構築する手順

## 全体像

```
プロジェクトルート/
├── CLAUDE.md                    # 1. プロジェクト設計書
├── .claude/
│   ├── skills/
│   │   └── <スキル名>/
│   │       ├── SKILL.md         # 2. マネージャーAI（入口）
│   │       └── references/      # 3. フロー定義（実行手順書）
│   ├── agents/                  # 4. エージェント定義
│   └── personal/                # 5. 個人設定（gitignore）
├── reference/                   # 参照資料（人間がメンテ）
└── output/                      # 成果物（gitignore、キュー等は除く）
    └── topic-queue.md           # 6. ジョブキュー
```

---

## STEP 1: CLAUDE.md を書く（プロジェクト設計書）

プロジェクト全体の設計を定義するファイル。以下を記載する:

- **コンセプト** -- 何を自動化するか、判断の方針
- **組織構成** -- マネージャーとエージェントの役割分担（ツリー図）
- **実行フロー** -- 手動 / 自動それぞれの流れの概要
- **ファイル構成** -- ディレクトリの役割
- **事業コンテキスト** -- ドメイン知識（ターゲット、ポジショニング等）

ポイント: CLAUDE.md は「全体の地図」。詳細な手順はここに書かず、スキルとフロー定義に分離する。

---

## STEP 2: スキルを作る（マネージャーAI = 入口）

`.claude/skills/<スキル名>/SKILL.md` がマネージャーAIの定義になる。

### マネージャーAIの責務

- ユーザーの指示を解釈し、適切なフローに振り分ける
- エージェントチームを起動する（`Agent` ツール + `run_in_background`）
- 品質ゲート（数値採点で合否判定）
- **自分では実作業しない**（リサーチも執筆もエージェントに振る）

### 振り分けルールの例

```markdown
| 指示の例              | 実行するフロー      |
|-----------------------|-------------------|
| 「記事書いて」          | note-flow.md      |
| 「LP作って」           | lp-flow.md        |
| `[自動モード]` 記事作成 | note-flow.md（自動）|
```

### 自動モードの仕組み

- 指示に `[自動モード]` が含まれていたら、キュー（`topic-queue.md`）から先頭1件を取得
- ユーザー確認なしで完走し、`draft-ready` で止まる（デプロイはしない）

---

## STEP 3: フロー定義を書く（実行手順書）

`.claude/skills/<スキル名>/references/` に、ステップごとの詳細な手順を書く。

### フロー定義に含める要素

1. **モード判定** -- 手動 / 自動で動作を切り替える分岐
2. **STEP 0: 準備** -- テーマ取得、重複チェック、チーム起動
3. **STEP 1〜N: 実行** -- 各エージェントへの指示テンプレート（SendMessage）
4. **品質ゲート** -- リーダーチェック（85点）→ マネージャーチェック（90点）の2段階
5. **完了処理** -- キューのステータス更新、台帳記録、チームシャットダウン

### 品質ゲートの設計例

| 項目 | 配点 | チェック内容 |
|------|------|-------------|
| ターゲット適合性 | 25点 | 読者が行動したくなるか |
| 事実の正確性 | 20点 | 数値・出典に誤りがないか |
| 差別化 | 20点 | 競合との違いが伝わるか |
| リスクチェック | 20点 | 誤情報・コンプラ問題がないか |
| UX | 15点 | 読みやすさ・導線の自然さ |

### 差し戻しループ

- リーダーが85点未満ならライターに差し戻し（最大3回）
- マネージャーが90点未満ならリーダーに差し戻し
- 感覚的に「OK」で通さず、必ず数値で採点する

---

## STEP 4: エージェントを定義する

`.claude/agents/` にエージェントごとの `.md` ファイルを作る。

### エージェント定義のフォーマット

```markdown
---
name: my-agent-name
description: 役割の1行説明
model: sonnet  # or opus
tools: Read, Write, Edit, Glob, Grep, Bash, SendMessage
---

あなたは〇〇です。

## あなたの役割
（何をする / 何をしない）

## 組織構造での位置づけ
（誰から指示を受け、誰に指示を出すか）

## 通信方法
（SendMessageの相手と形式）
```

### 組織設計のパターン例

```
マネージャーAI（Opus / 判断・品質チェック / メイン会話）
  ├── リサーチリーダー（Sonnet / 調査チーム統括）
  │     ├── リサーチャーA（Sonnet）
  │     └── リサーチャーB（Sonnet）
  └── ライティングリーダー（Sonnet / 構成設計・品質管理）
        ├── ライターA（Opus）
        └── ライターB（Opus）
```

### モデル選択の指針

- 判断・創作が必要 → Opus
- 管理・構成・検証 → Sonnet
- 単純チェック → Haiku

---

## STEP 5: ジョブキューを作る

`output/topic-queue.md` のようなMarkdownテーブルで、実行対象を管理する。

```markdown
## ステータス定義

| status      | 意味                          |
|-------------|-------------------------------|
| pending     | 未着手。スケジューラーが取得可能 |
| in-progress | 自動実行中                     |
| draft-ready | 下書き完了。レビュー待ち        |
| published   | 公開済み                       |

## キュー

| # | slug | テーマ | status | 実行日 |
|---|------|--------|--------|--------|
| 1 | ...  | ...    | pending | -     |
```

自動モードでは `pending` の先頭1件を取得 → `in-progress` に更新 → 完了後 `draft-ready` にする。

---

## STEP 6: スケジューラーを設定する（RemoteTrigger）

Claude Code の `/schedule` スキルで定期実行を設定する。

```
/schedule create
```

設定内容:
- **cron式**: 実行タイミング（例: `0 3 * * 1,3,5` = 月水金 3:00）
- **prompt**: マネージャーAIスキルを呼び出す指示（例: `/note [自動モード] 記事を作成してください`）
- **project**: 対象プロジェクトのパス

スケジューラーが起動すると、マネージャーAIがキューから取得 → チーム組成 → 実行 → `draft-ready` で停止。人がレビューしてからデプロイ指示を出す。

---

## STEP 7: オンボーディングを作る（複数人で使う場合）

`.claude/skills/onboarding/SKILL.md` で、対話的に個人設定を生成するスキルを作る。

- 名前、役割、文体の好み、NG表現などをヒアリング
- `.claude/personal/SKILL.md` に保存（gitignore済み）
- マネージャーAIが起動時に読み込み、品質チェックに反映

---

## .gitignore の設定

```
output/*
!output/.gitkeep
!output/topic-queue.md
!output/content-database.md
.claude/settings.local.json
.claude/personal/
```

成果物は基本gitignore。キューや台帳など、チーム共有が必要なファイルだけ追跡する。

---

## 応用のポイント

| 要素 | 役割 | 別ドメインで変えるところ |
|------|------|------------------------|
| CLAUDE.md | プロジェクトの地図 | ドメイン知識・組織構成 |
| SKILL.md | マネージャーAI（入口） | 振り分けルール |
| references/*.md | フロー定義（手順書） | ステップの内容・品質基準 |
| agents/*.md | 各エージェントの役割 | 役割・ツール・モデル |
| topic-queue.md | ジョブキュー | テーブルの列（ドメインに合わせる） |
| /schedule | 定期実行 | cron式・prompt |

この構造をそのまま別のドメイン（例: レポート作成、提案書作成、技術ドキュメント等）に置き換えれば、同じ仕組みで動く。

### 核になる設計思想

1. **マネージャーは判断だけ、実作業はエージェントに振る**
2. **品質ゲートは数値採点で、感覚で通さない**
3. **自動実行は `draft-ready` で止める。デプロイは人が判断する**
